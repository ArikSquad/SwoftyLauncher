## Question
Does Car_Upgrades_ApplyToVehicle replay each radUpgrade block once per car build (session load), and what perc does each block get for a career car?
One question only. If it splits into two, file two tests.

## Hypothesis
Car_Upgrades_ApplyToVehicle (sig car.upgrades_apply_to_vehicle) is called once per radUpgrade block per car when the car systems are built for a session, with xmm3 = clamp(sum of R&D progress) of that type; a second call with the same block name returns at once because the name is already in the applied vector CarLive+0x4b8 (begin +0x4c0/end +0x4c8). For each matched section, site_Car_UpgradeSectionApplyCall sees g_Car_UpgradeLerp = perc (xmm6). Static basis: subsystems/car.md#perf.

## User steps
1. Install the loader, core and swofty_trace.dll with the T112 runtime config.
2. Load an existing career save (My Team or Driver Career) with some R&D upgrades fitted.
3. Enter practice 1, drive out of the garage, return to the garage, quit to the career hub.
4. Enter the next session (or restart the session) and quit. Close the game and send swofty/trace.log.

## Expected log lines
- `E .* hook=t112.apply_block .* block="radUpgrade\w+"` -> the replay runs, with the block name and perc (xmm3)
- `E .* hook=t112.section_call .* xmm6=` -> per-section apply with the lerp value
Pass rule: per vehicle id, each block name appears once per session entry, xmm3 in 0..1, applied_end grows by 0x28 per block. Fail rule: the same block name repeats for one vehicle within a session with a different perc (then the once-per-build claim is wrong), or no apply events at all in career.

## Results
- Run: `2026-10-28-gp`, logs filed under `re/traces/T112/2026-10-28-gp/` (see its RUN.md).
- Verdict: partial
- Partial. In a Grand Prix the only block replayed is `medium` (the performance tier block), perc 1.0, equal_performance 0, for every car. It is replayed after every reset: 20 race cars after each of the two all-vehicle resets during loading (trace lines 145-164 and 226-245) and car 19 after each of its three per-vehicle resets (82, 296, 303), 43 calls in all. The applied-block vector was empty before every replay (begin == end), so each reset clears it. No `radUpgrade` block was replayed: a Grand Prix has no R&D.
- `t112.section_call` never fired, so the `medium` block changed no section in this session.
- Still needed: a career session with fitted R&D parts, to see the `radUpgrade` blocks and the perc they get; and why `medium` applies no section (check the VTF for an Upgrade child named `medium`).
- KB changes made: `Car_Upgrades_ApplyToVehicle` to L3 (`trace:T112/2026-10-28-gp:82`, `:145`, `:226`); `CarLive.applied_upgrades_begin` and `applied_upgrades_end` to L3 (`:164`, `:226`). Left at L2: `site_Car_UpgradeSectionApplyCall` (never hit), `g_Car_UpgradeLerp`, `g_Car_UpgradeLerpActive`, `CarLive.equal_performance` (0 for every car, the mode was not used).
