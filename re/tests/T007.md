## Question
At 26 cars, what overwrote the block header of the TYRE_SYSTEM wheel map's 32-bucket table before the heap 0x16 abort?

## Hypothesis
- `Sess_Veh_UpdateWheelMap` inserts each session vehicle's u8 index into the robin_hood map at TyreSystem+0x148. The TyreSystem object is built in the game-module constructor (0x1407e5420) with the allocator `getHeap("TYRE_SYSTEM")` and stored in a static global (0x1460806d8).
- The 26th distinct key grows the table from 32 to 64 buckets. The rehash then frees the 32-bucket table through `Ne_Heap_Free`, and `Ne_Heap_DeallocateNonSmall` rejects it with code 0x16 (line 0x4a4, "Failed to find address %p in the allocated list"). That error means the size word in front of the block (low 32 bits: block size; high 32 bits: requested size) does not match.
- The heap is not full in any of the 18 aborting sessions:
  - capacity (budget) is 0xc300000 and the limit 0x18600000;
  - about 0xa4xxxxx is used and about 0xe0xxxxx is free;
  - the largest free block is about 0xe0xxxxx (rbx, r13, r12, r15 at `Ne_FatalAbort`).
- So the abort is a corrupted (or foreign) block header, not an exhausted arena.
- The dump shows which of these it is:
  - the bytes in front of the table, written by an out-of-bounds write;
  - a table owned by the sub-allocator (heap+0x130 range) that took the wrong free path.
