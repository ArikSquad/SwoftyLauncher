# T127 Is site_Gdb_ReserveTarget hit exactly once per boot, before the first record insert, with rcx equal to the database file's record count and the value map still empty?

- Requested by: w7-sizing, 2026-10-28
- Status: draft
- Session: (filled by the lead when batched)

## Question
Is `site_Gdb_ReserveTarget` (0x1445a0a11, sig `gamedb.reserve_target`) hit exactly once per boot, before the first record insert, with rcx equal to the database file's record count and the value map still empty?

## Hypothesis
`Gdb_Load_GameDatabase` runs once at boot. At 0x1445a0a11 rcx = max(file record count, map.num_elements) and the map was just initialised, so rcx = file count = 742,857 on the stock database (the core's `before` count), `[rsp+0x88]` (the insert loop bound) equals it, `GdbValueMap.num_elements` = 0, `mask` = 0, `max_num_elements_allowed` = 0, `info_inc` = 0x20 and `GdbDatabase.loaded` = 0. Evidence: re/decomp/1445a0350.c, kb:subsystems/gamedb.md#value-map.

## Promotes
- `site_Gdb_ReserveTarget`, `gamedb.reserve_target`, `Gdb_Load_GameDatabase`
- `GdbValueMap.num_elements`, `GdbValueMap.mask`, `GdbValueMap.max_num_elements_allowed`, `GdbValueMap.info_inc`, `GdbDatabase.loaded`
Fail: a second hit, a hit with a non-empty map, or rcx != file count demotes the site to L1 and the sizing design (work/std16/W7-SIZING.md) is void.
