## Question
With the core raising the reserve target at `site_Gdb_ReserveTarget` past 838,860, does a profile that adds more than 838,860 records in total boot to the main menu with every record applied and no growth rehash?

## Hypothesis
The game reserves the value map for the target before inserting (`Gdb_Load_GameDatabase` -> `Gdb_HashMap_Rehash` on the empty map at 0x1445a0aa3). A target of 742,857 + 100,000 + 32 + 4,096 picks 2^21 buckets (growth point 1,677,721), so the core's runtime inserts after load never reach `site_Gdb_InsertGrowCall` and no record is freed. Without the sizing the same profile reaches the growth rehash, which frees every record (Gdb_HashMap_Rehash notes) and crashes at Gdb_Init_TableCursor+0x31c. The 1.5.11 file-route test already booted 843,179 records on a 2^21 map.
