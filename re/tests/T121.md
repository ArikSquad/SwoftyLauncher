# T121 Does g_Sess_VehicleTable index (CarLive.vehicle_id) equal the participant index, and does it stay stable for a whole session?

## Question
Does g_Sess_VehicleTable index (CarLive.vehicle_id) equal the participant index, and does it stay stable for a whole session?

## Hypothesis
Car_Chassis_Build assigns CarLive.vehicle_id = g_Sess_VehicleCount++ at `site_Car_RegisterVehicleId` (sig `car.register_vehicle_id`, al = id, rdi = CarLive) and Car_Destroy_Live removes cars by swap-with-last, so the id is a dense slot. If the session spawns cars in participant order, id = participant index (EntrantRecord byte +0x82 looks like the vehicle index, entrants lane L1). A mid-session car removal would renumber the last car.

- `t121.register .*id=(\d+)` lines with ids 0..N-1 in spawn order → dense ids.

Pass rule: ids 0..N-1 appear once each and the team order matches the participant order. Fail rule: gaps, repeats, or a different order.

## Results
- Run: `2026-10-28-gp`, logs filed under `re/traces/T121/2026-10-28-gp/` (see its RUN.md).
- Verdict: partial
- Partial. `site_Car_RegisterVehicleId` gave ids 0..20 in create order (lines 18-78), dense, and they stayed the same for the session (21 removals at the end). Id 20 is the safety car (1734 kg, no ERS; `snap-grid.txt:39`).

- The player's car is most likely id 19: the only car with controller-change resets (T120) and with its own setup (T113). The participant mapping itself was not established (no telemetry participant list was joined).
- Still needed: a session where the player drives, joined with the UDP participant list or `EntrantRecord+0x82`.
