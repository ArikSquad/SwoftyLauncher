## Results
- Run: `2026-10-28-gp`, log filed under `re/traces/T126/2026-10-28-gp/bink.log` (see its RUN.md).
- Verdict: answered.
- The recap file reports 30 track ids: index 0 → id 10, indexes 1..8 → ids 11..18, 9..17 → 20..28, 18..29 → 40..51 (summary line 557). The game reads the ids from several callers; the pair 0x143f8b46c then 0x143f8b54c walks indexes 0..18 only (line 355: index 18 → id 40).
- With the game in English the game kept three tracks open for playback (caller 0x143f8b5d2): index 9 (id 20), index 0 (id 10) and index 18 (id 40) (lines 508, 510, 549). Earlier opens from 0x143f8b3c2 and 0x143f8b090 / 0x143f8b13c open and close a track at once (probes).
- Reading: id 10 is the always-on music and effects bed and id 40 the English voice track, so the other languages sit in ids 11..28. What id 20 carries is not known. The UI wipe videos have one track (index 0 → id 0).
- Still needed: the language → id table, which sits in the selector around 0x143f8b46c..0x143f8b5d2; decompile it to get the Japanese and Korean ids statically. A core hook on `BinkOpenTrack` can then swap the requested index for the index that holds id 40 (English) or any other language.
- KB changes made: none (no KB rows for the Bink callers yet).
