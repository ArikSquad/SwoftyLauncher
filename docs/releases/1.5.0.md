# 1.5.0

Swofty Launcher for F1 25 1.5.0 starts with a one-time setup that gives every player a clean record of their original game files. Addons that run code now work on the EA app copy, **ADDON SETTINGS** scrolls sideways, and installing an addon from the Addon Browser brings the addons it needs. The launcher starts faster and scrolls smoothly, and the installer finds and moves earlier installs.

## One-time setup

The first **Play** after updating opens a short setup. See [Windows](/guide/windows#_3-play) or [Linux](/guide/linux#_3-play).

1. Say whether your game folder holds mods Swofty didn't add, read the note about outside tools and select **I understand**. Swofty puts back the files it changed and starts its record of your original game files over.
2. Verify the game files in Steam, or repair the game in the EA app. On a Steam copy whose file list the launcher can read, answering no skips this step: the launch checks every game file against Steam's own list.
3. **Play** carries on. The first launch after the setup can take 5 to 8 minutes; a notice says so. Don't press Play in Steam or the EA app while it runs.

- **I've verified, continue** stays off until you open the verify, and while Steam is verifying or updating F1 25. Every launch also waits while Steam does.
- When the old record can't put a file back, the setup carries on for a Steam or EA app copy and says so; verifying puts the file back.
- From the command line: `swofty setup status`, `swofty setup reset [--other-mods]` and `swofty setup done`. A launch from Steam's own Play button stops with a message until the setup is done.

## The EA app copy

- Addons that run code work on the EA app copy. SwoftyMod loads before the game reads its database, so addons' database edits apply, and their engine hooks install. R&D: Tyres & Thermal Management, Career Mode Editor and **ADDON SETTINGS** work there.
- On Linux, the launcher sets Wine to load its loader for F1 25 in the EA app's prefix before it starts the EA app. When the EA app is already open the first time, the launcher closes it and starts it again.
- Addon pages such as Career Mode Editor follow the copy the game runs from, so switching between the Steam and EA app copies no longer leaves a page reading the other copy.

## ADDON SETTINGS

- With more than three columns of tiles, moving past the edge slides the row along by a column, and coming back from an addon's page slides it to the tile you opened. Based on Giggles' Addon Settings Overhaul.
- An addon's author, version and description show only on the highlighted tile.

See [In-game addon settings](/using/swofty-mod).

## Addon Browser

Installing an addon also installs the addons it requires, each at the newest version that matches and works with your launcher. The addon's page lists **Also installs**, and **Missing requirements** names any required addon the Addon Browser doesn't have. See [Addon Browser](/using/addon-browser#requirements).

## Launcher

- The launcher starts faster and scrolls smoothly with the mouse wheel. Thanks to ArikSquad.
- Every list and page that scrolls shows a scrollbar.
- Simplified for Swofty's pages come from its manifest. Thanks to Team Simplified.
- **Send Logs** asks what went wrong, and warns when no game launch is on record yet.
- The **Your game files have been edited** dialog has **Verify game files in Steam**.
- When Windows Smart App Control blocks the launcher, the message says so and how to allow it.
- The launcher reports how each game session ended, and a game closed with **Stop** counts as stopped, not crashed.

## Fixes from your reports

- A track package without a base track is left out with a warning naming it, instead of failing the launch.
- An AI racing line resource whose stats no longer match its data gets them rebuilt, so the game can't read past it. This was a crash on some imported tracks.
- A DB Editor change that raises a table's row count above the rows the database holds keeps the count at those rows. This was a crash at boot.
- Menu files that an addon edits in place keep their layout, so mods such as the 2012 Season mod load.
- An addon's own era picker menu stays as the addon made it when the era rows can't be added.
- Copied customisation items, such as suits and helmets, keep their colour defaults. This was a crash at boot.
- When the loader doesn't load into the game, the logs name what kept it out.

## Installer

- The installer finds earlier installs: in the default folder, behind your shortcuts, from a running launcher and from folders you picked before. It offers to move them into the folder you choose.
- It closes a running launcher first, and doesn't install while F1 25 runs.

The installer is at [SwoftyLauncherInstaller.zip](https://github.com/Swofty-Developments/SwoftyLauncher/raw/main/installer/SwoftyLauncherInstaller.zip).

## For addon makers

- An addon's `requires` now installs from the Addon Browser. See [Requirements](/reference/addons/manifest#requires-conflicts-load-after).
- A screen with `"page": "options"` shows your addon's options on a screen of its own. Thanks to Team Simplified.
- A plugin's `sections` list its sidebar pages without starting the plugin, and a `sections/<id>.svg` sets a page's icon.
- `tools/gfx_material.py` reads, writes and converts F1 23 and F1 25 material resources.
- The knowledge base decodes the tyre force model, the physics step and the powertrain. Thanks to vogtmarcel.
