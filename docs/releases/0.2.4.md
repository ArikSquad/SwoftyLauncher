# 0.2.4

Swofty Launcher for F1 25 0.2.4 updates the offline play extension to 0.3.0. Modded sessions now work on protected game builds — the EA-app copy included — where the launcher previously refused because the game's launch check could not be located statically.

Download it from [Releases](https://github.com/Swofty-Developments/SwoftyLauncher/releases). The launcher offers each new release itself.

## Offline play

- The game's launch check was reverse-engineered end to end: it finds the game's parent process, reads the parent's image path and verifies that file's Authenticode signature. That is why it fires with `Game launch error. Error code: 0x00000004` when a session is started without the real launcher.
- The extension now has two methods and picks per build. Unprotected builds keep the proven static patch, applied before the game's first instruction. Protected builds — where the check is hidden where no pattern matching can reach it — use the runtime signature method: the check's signature query is redirected to the real EA-signed launcher file, staged alongside the game for the session. The check reads a genuinely EA-signed file and passes on its merits.
- The launcher accepts protected builds now. It still refuses anything it cannot identify, and every step is logged to `swofty/loader.log`, including `launcher-signature check redirected to the signed launcher` when the method arms.
- Sessions remain offline and unchanged in scope: EA AntiCheat is not started, multiplayer is unavailable and cannot be enabled, and the game folder returns to vanilla when the game exits.
