# 0.2.1

Swofty Launcher for F1 25 0.2.1 updates itself, loads the textures and models that Simplified Studio packages carry in the shader archives, builds the remaining ERP ops and fixes blank in-game dialogs. Team Simplified contributed the shader archive and team logo work.

Download it from [Releases](https://github.com/Swofty-Developments/SwoftyLauncher/releases). From this version on, the launcher offers each new release itself.

## Updates

- The launcher checks GitHub for a newer release at most every 6 hours. A bar above the play bar shows the new version with **Release notes**, **Skip this version** and **Update**. `"updates": { "check": false }` in `config.json` turns the check off.
- **Update** downloads the archive for your platform, checks it against the release's `SHA256SUMS`, replaces `bin/`, `loader/` and, on Linux, `share/`, then offers **Restart**. It does not update while F1 25 runs.
- If an update stops partway, the next start of the launcher or `swofty update` puts the previous version back.
- A copy that does not run from a release folder, such as a Nix install or a development build, links to the release page instead.
- `swofty update` installs the newest release and `swofty update --check` reports it.

## Mods

- Mods made with Simplified Studio keep cars, liveries and logos inside `shader_package_2025/`. Those resources now load at boot, so the cars, liveries and logos show in game, not only the database and text changes.
- Team logos from several mods merge into the game's logo arrays slice by slice, and the mod lower in the list wins. An array made for an older game merges the slices it has. An array of another format is used whole, with a warning.
- A mod that renames teams no longer reverts the team names another mod sets.
- Writes that repeat the value already in place and Simplified Studio's `tools_package` marker no longer show as conflicts, and a mod no longer conflicts with itself.
- Removals in a mod now apply. A mod that removes resources builds every ERP change into the game files, because the in-game loader cannot remove a resource from a stock archive.
- The comparison of each mod with the game runs again on the first build after updating.

## Asset API

- `erp.replace-resource`, `erp.add-resource`, `erp.remove-resource` and `erp.add-mipmaps` are built. Replace and add work on the build and runtime routes, remove works on the build route, and add-mipmaps places the mip files in the game folder. See [ERP operations](/reference/ops/erp).

## Fixes

- In-game dialogs, such as quitting the game, quitting a session and leaving photo mode, show their text again. The SwoftyMod changelog popup no longer changes the game's shared popup labels.
- After the game quits, the play bar says **Restoring the game files…** instead of **Launching…** until the game files are back.

## Building

- The in-game loader builds on Windows with `native/build-win.sh`.
